Meeting Translator user flow

Desktop Chrome/Edge · in-person microphone or online tab plus microphone · English ↔ 简体中文

1Open app
Choose English/中文 interface. No account is requested.
↓
2Configure source
Select In-person microphone or Online tab + microphone, choose the microphone, and choose translation direction.
↓
3Acknowledge cloud processing
Explain that live audio is sent to OpenAI and that this app does not save audio or transcript content. State that default /v1/realtime abuse-monitoring logs may be retained up to 30 days, with configured provider controls recorded separately. Only after acknowledgement request browser permissions.
↓
4Start capture
Normalize audio to one stream. Online mode mixes selected tab audio and local microphone. Establish a short-lived server session and authenticated WebSocket subprotocol.
↓
5Live translation
Client VAD opens an utterance, streams 20 ms PCM frames, and commits after 650 ms of silence. Show interim source text; on completion show relative timestamp, source text, and natural target translation.
↓
6Control the session
Pause/resume capture, switch direction for the next utterance after acknowledgement, scroll through entries, return to live, or copy source/translation pairs. Backpressure pauses capture rather than dropping audio.
↓
7Recover failures
Show an actionable permission, capture, connection, or provider error. Preserve finalized source text. Retry translation by resubmitting source text/context without retransmitting audio; reconnect starts a new session.
↓
8Stop or expire
Flush an active utterance for up to two seconds, close the provider stream, discard server memory, and return to configuration. Refresh or tab close may discard the active transcript.
