Meeting Translator system architecture

One ephemeral session, one normalized audio stream, one transcription path, one translation path.

Browser client

React/Vite UI, consent, device picker, tab capture, microphone capture, AudioWorklet, reducer/context.

Outputs: JSON controls + binary 24 kHz PCM.

→

Fastify + ws server

REST session setup, token validation, WebSocket protocol, in-memory session, event mapping, retry control.

Secrets: provider key stays here.

→

Provider adapters

OpenAI Realtime transcription session for interim/final source text. Text-model adapter for finalized translation.

Retention: no app-side persistence.

Control plane: POST /v1/sessions creates an opaque token; WS /v1/sessions/{id}/stream carries controls, PCM, and live events.
Data plane: Browser audio → AudioWorklet normalization/mix → server → Realtime transcription → finalized source → text translation → browser entry.
Failure plane: Permission/capture/provider errors become typed client states; finalized source is preserved; retry translation does not retransmit audio.
Persistence boundary: No database, transcript file, audio file, or content logs. Only bounded in-memory context exists during a session.
